TreeTime API — מדריך שילוב

כל מה שצריך כדי לדבר עם השרת בצורה תקינה — אימות, כותרות חובה, ודוגמאות.
📘 תיעוד אינטראקטיבי (Swagger) 🩺 בדיקת תקינות שרת

1. שתי דרכי אימות

משתמשים JWT Bearer Token — לאפליקציית הווב/מובייל, לכל עובד שמתחבר עם אימייל+סיסמה. 
POST /api/auth/login
Content-Type: application/json

{ "email": "you@company.com", "password": "••••••••" }
התגובה מכילה token. יש לשלוח אותו בכל קריאה הבאה: 
Authorization: Bearer <token>
אינטגרציות API Key — למערכות חיצוניות (שכר, Slack, וכו'). נוצר ע"י admin דרך POST /api/api-keys ומוצג פעם אחת בלבד — יש לשמור אותו. 
X-API-Key: tt_xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx
לכל מפתח יש הרשאות (scopes): read, write, admin. קריאה שדורשת write ולמפתח יש רק read — תיכשל עם 403.

2. כותרות חובה בכל קריאה

כותרתערךמתי
Content-Typeapplication/jsonבכל בקשה עם גוף (POST/PATCH)
AuthorizationBearer <token>משתמש מחובר (אפליקציה)
X-API-Keytt_...אינטגרציה חיצונית

יש לספק אחת מהשתיים — Authorization או X-API-Key — אחרת התגובה תהיה 401 missing_credentials.

3. דגם נתונים בקצרה

ישותהסבר
employeesעובדים. role: employee / manager / admin
projectsפרויקטים/לקוחות לשיוך דיווחי זמן
time_entriesרשומת דיווח זמן. ended_at = NULL = טיימר רץ כרגע
api_keysמפתחות לאינטגרציות (admin בלבד)
webhooksהרשמה לקבלת עדכונים בזמן אמת

4. זרימת עבודה טיפוסית — טיימר בסגנון Toggl

POST /api/time-entries/start   { "project_id": 3, "description": "פגישת לקוח" }
   → מחזיר רשומה עם ended_at = null

POST /api/time-entries/stop    {}
   → סוגר את הרשומה הרצה, ended_at מתעדכן

GET  /api/time-entries/current
   → בודק אם יש טיימר רץ כרגע (לרענון UI אחרי ניתוק)

הערה: אם משתמשים ב-API Key (לא JWT), יש לצרף employee_id בגוף/query של כל קריאה — המפתח לא מזהה עובד ספציפי.

5. Webhooks — לקבלת עדכונים בזמן אמת ממערכות חיצוניות

נרשמים דרך POST /api/webhooks (admin בלבד) עם כתובת יעד ורשימת אירועים: time_entry.created, time_entry.started, time_entry.stopped.

כל אירוע נשלח כ-POST ל-target_url שלכם, עם כותרת חתימה לאימות מקור: 
X-TreeTime-Signature: sha256=<hmac-sha256 of body, using your webhook secret>
יש לאמת את החתימה בצד שלכם לפני שמתייחסים לבקשה כאמינה.

6. קודי שגיאה נפוצים

קודמשמעות
401 missing_credentialsלא סופקה כותרת אימות
401 invalid_token / invalid_api_keyאימות שגוי/פג תוקף
403 forbidden / insufficient_scopeאין הרשאה מספקת לפעולה
409 timer_already_runningניסיון להתחיל טיימר כשכבר יש אחד פעיל
400 validation_errorשדות חסרים/לא תקינים בגוף הבקשה
